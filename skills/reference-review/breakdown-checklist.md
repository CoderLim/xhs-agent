# Reference Breakdown Checklist

Use this checklist when reviewing a reference note.

The goal is to learn the demand, structure, and expression pattern. Do not reuse someone else's personal story, image, or unsupported claim.

## 1. Should this reference be reviewed?

Check:

- Is it in the same or adjacent niche?
- Is the account size not too far from the user's stage?
- Is the reference recent enough to be useful?
- Does it show strong interaction compared with the account size?
- Do the comments show real demand?

The source notes mention these practical signals:

- low-follower but high-interaction accounts are useful references
- recent posts are more useful than old posts
- repeated appearance on the home feed can be a signal
- comments such as requests, questions, or need statements can reveal demand

## 2. Reader / Scene / Problem / Outcome

Extract the basic unit:

```text
Reader:
Scene:
Problem:
Outcome:
```

If this cannot be extracted, the reference is not clear enough.

## 3. Title Breakdown

Check which title pattern it uses:

- reader + pain + solution
- pain question + missing cause
- number + method + result
- identity + scene + change
- misunderstanding + correct view
- collection / save-worthy title
- positive stimulus
- negative stimulus

Also record:

```text
Core word in front:
Number used:
Pain point:
Result promise:
Suspense or contrast:
Risk level:
```

## 4. Cover Breakdown

Record:

```text
Main text:
Supporting text:
Visual type:
Information hierarchy:
Scene or contrast:
```

Common cover patterns:

- pain cover
- result cover
- comparison cover
- collection cover
- scene cover

## 5. Body Breakdown

Check whether the body follows one of these:

```text
痛点共情 -> 原因点破 -> 给出方案 -> 行动引导
```

or:

```text
痛点共情 -> 原因点破 -> 给出方案 -> 示例演示 -> 行动引导
```

Record:

```text
Opening hook:
Reason explained:
Steps or solution:
Example:
Ending action:
```

## 6. Comment Demand

Extract user demand from comments:

- repeated questions
- requests for templates
- requests for specific scenes
- objections or confusion
- people asking for next steps

Turn each demand into a possible topic.

## 7. Keyword Layout

Record:

```text
Title keywords:
Body long-tail keywords:
Tag keywords:
Search-intent words:
```

The source notes mention title core words, body long-tail words, and tag expansion words.

## 8. Reusable vs Not Reusable

Reusable:

- reader demand
- scene
- problem angle
- structure
- title formula
- cover information hierarchy
- comment demand

Not reusable:

- personal story
- personal identity claim
- image
- full wording
- unsupported metric
- fake experience
